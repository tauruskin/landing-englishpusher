### N1 — [stage-1] The AC-08 trap-field step cannot produce its expected result

- **Where:** `release-checklist.md:80-82`; the input is at `TrialForm.tsx:290-296`.
- **AC:** AC-08.
- **Problem:** `company_url` is a controlled React input. Typing into it from the Elements panel
  fires no `onChange`, so `honeypot` stays empty and a real request is sent. The checkbox fails
  even though the trap logic is correct.
- **Verdict:** Fix now. Focus the input from the console, type a real key, then send a valid form.

### N2 — [stage-1] The offline-failure row leaves out the retry clause

- **Where:** `release-checklist.md:88-90` against `spec.md:297`.
- **AC:** AC-05.
- **Problem:** The test-plan row ends with "trying again records one more error". The checkbox
  checks only the first failure.
- **Verdict:** Fix now. Add: press Send again while still offline → one more `trial_form_error`
  with `error_kind: "network"`, and still no `generate_lead`.

### N3 — [stage-2] The "no text outside FORM_COPY" guard is easy to bypass

- **Where:** `src/lib/formCopy.test.ts:42-45`.
- **AC:** AC-10.
- **Problem:** The guard misses `{"…"}` literals, template literals, ternaries, `alt={'…'}`,
  unlisted `aria-*` attributes, module-level constants, and text runs that contain `;` or `=`.
  The reviewer confirmed each bypass with a probe script.
- **Verdict:** Fix now. Widen the regexes to catch string literals inside expression containers
  and ternaries and any `aria-*` / `alt` / `title` / `placeholder` attribute in either quote form.
  Apply the `;`/`=` filter only to runs that start after `}`.

### N4 — [stage-2] Validation messages and pill labels are outside FORM_COPY and the approval pointer

- **Where:** `src/lib/validate.ts:12-15`, `src/lib/formCopy.test.ts:2`,
  `release-checklist.md:50-52`.
- **AC:** AC-10.
- **Problem:** The validation messages are never scanned by `findPromises`. The checklist tells
  Tetiana that every form string is in `FORM_COPY`, so her approval pass would skip
  `validate.ts` and `options.ts`. Keeping the app's messages in `validate.ts` is correct (AC-02).
- **Verdict:** Fix now. Scan the `validateTrialForm` messages (the empty form and the
  invalid-email case) in `formCopy.test.ts`. Name `validate.ts` and `options.ts` alongside
  `FORM_COPY` in the checklist and the test header.
