### Q1 — [stage-2] Text returned by a local helper function passes the guard

- **Where:** `src/lib/jsxText.ts:87-91`.
- **AC:** AC-10.
- **Problem:** `rendered` looks into a call's callee only when it is a property access (`xs.map`),
  and into arrow-function arguments only. The guard returns `[]` (probed) for
  `const submitLabel = (s) => s === "sending" ? "Sending…" : FORM_COPY.submit` rendered as
  `{submitLabel(status)}`, and for the same helper written as a `function` declaration.
- **Why it counts:** It is a plausible next edit: `pillClass` (`TrialForm.tsx:35`) is already a
  helper in this style, and a "Sending…" label is a natural addition. The approval checklist
  would not catch it, because it points to the three copy files.
- **Verdict:** Fix now.
  - When a call's callee is an identifier, walk the returns of its declared arrow or function
    initializers and of a `function` declaration with that name.
  - Reuse the cycle guard.
  - Add caught cases for an arrow helper and a function declaration, and an ignored case for a
    `pillClass`-style helper used only in `className`.

Not findings:

- Lower-likelihood bypasses: `useState("…")`, destructuring, shorthand or quoted object keys,
  `satisfies`, tagged templates.
- Fail-safe over-matches: name collisions across scopes, digit-only counters.
- Nested-ternary blow-up: needs code nobody writes.
- No test pins the cycle guard; removing it would overflow the stack rather than pass silently.
- Commit trailers are separated from `Co-Authored-By` by a blank line, on every commit of the
  branch.
