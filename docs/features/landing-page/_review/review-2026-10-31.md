### F1 — [stage-1] The release checklist leaves out the manual UI rows the test plan sends to it

- **Where:** `docs/features/landing-page/release-checklist.md:43-66`; the test plan's CI placement
  is at `spec.md:368-370`.
- **AC:** AC-01, AC-02, AC-03, AC-04, AC-08, AC-09.
- **Problem:** The spec says every e2e-through-UI row runs by hand from the release checklist
  before each release. The checklist covers only these:
  - AC-13: local send.
  - AC-05 and AC-08: offline failure.
  - AC-03: focus, through the screen-reader pass.

  These checks have no checklist row, so nothing repeatable proves them at release:
  - AC-01: the thank-you greets by first name, then exactly one `generate_lead`.
  - AC-02: both messages are shown, the cursor lands on First name, nothing is sent.
  - AC-03: answers are kept across openings with one `trial_form_open` each, and a reload clears
    them.
  - AC-04: `#trial-lesson` is removed on close and the form doesn't reopen.
  - AC-08: a throttled send shows the sending state; a filled trap field gives a thank-you and
    sends nothing.
  - AC-09: a known email gets the same thank-you.

  The gap goes back to the T11 breakdown.
- **Verdict:** Fix now. Add a "Local UI pass (preview, Test form)" block to checklist §2, with one
  checkbox per row, each naming its AC.

### F2 — [stage-2] The automated AC-10 copy scan never sees the form's copy

- **Where:** `scripts/built-page.test.ts:10,30-34`; `src/components/trial-form/TrialDialog.tsx`
  renders nothing until the form opens; `src/lib/copyRules.test.ts:10-11` holds hand-copied
  literals.
- **AC:** AC-10.
- **Problem:** `dist/index.html` has none of the form text: headline, subline, goal labels,
  thank-you, send-failed banner. An edit to those strings in `TrialForm.tsx` would not be caught.
- **Verdict:** Fix now. Move the form's user-facing strings into one exported `copy` object (the
  checklist already says the wording lives there) and run `findPromises` over it in a src test.

### F3 — [stage-2] Two test-plan edge cases have no test

- **Where:** `src/lib/hubspot.test.ts:102-112` and `:126-139`.
- **AC:** AC-05, AC-09.
- **Problem:** Two cases from the test plan have no assertion:
  - `spec.md:325`: when the answer arrives just before the 15-second cut-off, the answer is used.
  - `spec.md:306`: nothing in the answer body changes the result.

  The code is correct today. This finding guards against a future regression only.
- **Verdict:** Fix now. Add two tests:
  - (a) a 200 that arrives at 14,999 ms under mock timers returns `{ok:true}`;
  - (b) a 200 with a body that says the contact already exists returns `{ok:true}`.
