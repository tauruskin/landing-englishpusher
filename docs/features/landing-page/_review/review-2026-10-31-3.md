### P2 — [stage-2] Constants declared inside a component pass the guard

- **Where:** `src/lib/jsxText.ts:30-37`.
- **AC:** AC-10.
- **Problem:** The guard only resolves top-level `const NAME = "<string>"`. These still pass:
  - a constant inside the function body;
  - a constant with a ternary or template initializer;
  - a `let`;
  - a field of an object constant.

  The reviewer rates this medium likelihood: a local `const cta = … ? "Try again" : …` is the most
  natural next edit.
- **Verdict:** Fix now. Collect declarations from every scope and keep the initializer node. Run
  the rendered-value check on it when the name is rendered, including object fields. Add test
  cases for each form.

### P3 — [stage-2] The text test only looks for ASCII letters

- **Where:** `src/lib/jsxText.ts:22`.
- **AC:** AC-10.
- **Problem:** `<p>₴500</p>` passes, though a price is banned (`spec.md:189`). Text made only of an
  entity, such as `&nbsp;`, would be flagged.
- **Verdict:** Fix now. Strip HTML entities, then test for Unicode letters, digits and currency
  symbols. Add a price case that must be caught and an `&nbsp;` case that must be ignored.

### P4 — [stage-2] The tracker title for T15 describes the rejected method
